# 06 · 决策记录（ADR）

格式：背景 → 决策 → 理由 → 后果。新的决策追加在末尾，不修改历史条目。

---

## ADR-001 · 产品定位：注意力审计，不是时间记录

**背景**：市面上时间记录工具已经饱和（RescueTime、Toggl、ActivityWatch），
纯记录没有差异化，且会被开源项目迅速做平。

**决策**：产品的核心是"判定 + 对账"，记录只是输入。

**理由**：用户的真实痛点是"我自报 6 小时但实际只有 3 小时，且不知道为什么"。
记录解决"花了多久"，判定解决"值不值"，对账解决"差在哪"。后两者没有成熟竞品。

**后果**：所有功能优先级以此为准。"再加一个应用分类统计"这类需求一律降级。

## ADR-002 · 技术栈改为 .NET 8 + WPF（否决 Tauri + Rust）

**背景**：初版方案定为 Tauri 2 + Rust + React。

**决策**：改为 .NET 8 + WPF + SQLite。

**理由**：
1. 本机 `rustc`/`cargo` 不存在，且无 MSVC Build Tools；装齐约 3–4 GB，可能需要管理员权限。
2. 媒体播放检测依赖 WinRT SMTC，在 .NET 中是原生能力，在 Electron/Tauri 中需要额外桥接。
3. 项目负责人**完全不写代码**，所有交付由 AI 完成，因此选择"AI 出错率低 + 环境依赖少"的栈优于"理论性能最好"的栈。
4. WPF 托盘、自启、单实例、单文件发布都是成熟路径，无插件依赖。

**后果**：
- 放弃跨平台（macOS 需重写 Collector，Core 不受影响）。
- UI 表现力下降，需在 M2 验收时评估；不达标则把呈现层换成 WebView2 + React（见 `04-architecture.md` §7）。
- 安装包约 60–90 MB，高于 Tauri 的 15 MB，可接受。

## ADR-003 · 许可证选择 MPL-2.0

**背景**：需要在"建立信任"与"保留商业化空间"之间取得平衡。

**决策**：Mozilla Public License 2.0。

**理由**：
- 这个品类**信任就是产品**，闭源等于自杀；但完全放任（MIT）又会让云厂商直接把代码包装成付费 SaaS。
- MPL 是**文件级 copyleft**：修改 FocusLedger 的文件必须开源，但可以被更大的、不同许可证的产品引用。
  这比 AGPL 更容易被商业用户接受，比 MIT 更能保护作者。
- 保留将来做闭源 Pro 外壳的可能（Pro 外壳不修改 MPL 文件，只引用）。

**后果**：
- 必须保留版权声明与变更说明。
- 引入贡献者后需要 DCO（Developer Certificate of Origin），避免将来无法调整许可策略。

**备选**（记录备查）：AGPL-3.0（更强保护但吓退企业用户）、MIT（最大传播但放弃护城河）。

## ADR-004 · 静默专注阈值与两遍制

**背景**：用户要求"按你的判断设置静默专注阈值"。
难点在于"无输入"既可能是深思，也可能是离开。

**决策**：
1. 阈值按应用类别区分：阅读类 600 s，打字类 300 s，其他 300 s。
2. 引入**两遍制**：实时给 provisional，日终用"返回修正"给 final。
3. 返回修正只覆盖 ≤ 600 s 的间隔，且要求前后同一应用、确实有回归输入；权重 0.40。

**理由**：
- 单一阈值无法同时满足"读 PDF 不滚动"和"离开去泡咖啡"两种情形。
- 不在当下猜测，而是等更多证据再判定，是对用户最诚实的做法。
- 0.40 的低权重承认了不确定性，而不是把它当成确定的学习时间。

**后果**：UI 必须区分"实时"与"已校正"，否则用户会觉得数字在跳动。

## ADR-005 · 不做摄像头 / 眼动检测

**背景**：摄像头能显著提升"是否在看屏幕"的准确率。

**决策**：永久排除，不作为可选特性。

**理由**：
- 目标用户（学生、研究者、ADHD 群体）对摄像头监控极度敏感，一旦出现，产品的信任叙事崩盘。
- 隐私合规成本（PIPL/GDPR 下的生物识别信息属敏感个人信息）远超准确率收益。
- 开源项目一旦有摄像头权限，会被立刻贴上"间谍软件"标签。

**后果**：静默专注的准确率上限被锁定，靠两遍制与用户复核弥补。

## ADR-006 · 先开源，商业化延后

**背景**：用户表示"先在 GitHub 开源了再说，商业化之后考虑"。

**决策**：M4 完成开源发布，Pro 版与定价在获得真实用户反馈后再定。

**理由**：这个品类的冷启动靠口碑与信任，闭源早期无人敢装一个记录自己全天行为的软件。
开源同时是获客手段和风险对冲。

**后果**：早期不投入任何授权、支付、账号体系的开发。所有架构决策优先"可被审计"，而非"可变现"。

## ADR-007 · 窗口标题本地保存，导出脱敏

**背景**：窗口标题是分类准确率的关键，但可能包含文件名、邮件主题、聊天对象等敏感信息。

**决策**：本地数据库保存完整标题；任何导出（CSV/JSON）默认脱敏；提供"严格模式"只保存标题哈希。

**理由**：本地保存的风险可控（用户自己的机器、自己的数据），导出才是泄露的主要路径。
一刀切不存标题会让分类准确率大幅下降。

**后果**：README 与隐私政策必须明示这一点，不能含糊。

## ADR-008 · 媒体播放判断优先于空闲判断

**背景**：初版决策顺序把"空闲"放在"媒体播放"之前。

**决策**：调整顺序为 locked → off_task → 媒体 → 空闲 → 输入 → 画面 → 静默。

**理由**：看网课时用户完全不碰键鼠，空闲时长会持续增长到几十分钟；
若先判空闲，45 分钟的网课会被整体误判为"离席"，这是最严重的误判类型（把学习算成没学习）。

**后果**：`02-state-machine.md` §3 的次序不可调整，任何改动都必须重跑场景矩阵。

## ADR-009 · 项目命名 FocusLedger

**背景**：需要一个能直接表达"对账"含义的名字。

**决策**：仓库名 `FocusLedger`，中文名「专注账本」。

**理由**：Ledger（账本）直接对应产品核心动作"对账"；`Focus` 说明领域；英文名在 GitHub 上易搜索、易记。
备选 `Attest`（作证）虽更贴合"取证"，但词义偏冷，不利于传播。

**后果**：所有命名空间、包名、可执行文件名统一使用 `FocusLedger`。

## ADR-010 · 应用层禁止出站网络请求

**背景**：隐私承诺需要可验证，而不只是写在 README 里。

**决策**：MVP 内应用层零网络代码；CI 中加入反射扫描测试，发现 `HttpClient`/`WebRequest`/`Socket` 使用即失败。

**理由**：可验证的承诺才是承诺。将来加云同步时，必须新开一个显式的、默认关闭的模块，并同步修改该测试的白名单。

**后果**：所有更新检查、崩溃上报、遥测一律不做（自动更新由安装器层负责，不在应用进程内）。
