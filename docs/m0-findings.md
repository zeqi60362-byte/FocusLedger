## 3. 关键发现

### 3.1 这组数据恰好复现了"番茄钟骗局"

运行期间用户并未操作电脑（`idle` 从 194 s 涨到 205 s），但**前台窗口一直是 WPS 且标题是一个正式的文档**。
如果使用番茄钟，这 12 秒会被记为"学习"；而按本项目的判定模型：

- `idle = 205 s`，尚未超过 `IDLE_MAX_TYPING = 300 s`
- `A = 0`（无输入）、`V ≈ 0.008`（画面几乎不变）
- 因此判为 `silent_focus`，权重 0.5，**低置信**
- 若继续到 300 s 仍无输入且无媒体播放 → 转 `idle_away`，权重 **0**

这正是设计想要的行为：不立刻下结论，但也不假装它是有效学习。

### 3.2 dHash 阈值需要真实动态样本校准

静止文档的 delta 只有 0–1。按 `02-state-machine.md` 的公式 `V = mean(delta) / 12`，
需要平均 delta ≈ 3 才越过 `V > 0.25` 的阈值。

本次运行用户没有操作，**没有采到滚动、切页、视频播放的动态样本**，因此
`12` 这个归一化分母目前只是估计值。M1 需要在真实使用 24 小时后，用实际 delta 分布重新标定。

**待办**：M1 结束时输出 delta 的 P50 / P90 / P99，据此确定分母与阈值。

### 3.3 PowerShell 5.1 的三个坑（实现时不要重犯）

1. **多维数组表达式下标**：`$arr[$y, $x + 1]` 在 5.1 下会被解析成三个下标并抛异常。
   改用一维数组 `$y * 9 + $x` 索引。
2. **窗口矩形越界**：最小化窗口的 rect 为 `-32000`，未裁剪直接截屏会抛异常。
   必须先判 `IsIconic`，再把矩形裁剪到 `VirtualScreen` 范围内。
3. **脚本编码**：含中文的 `.ps1` 必须存为 **UTF-8 with BOM**，否则 5.1 按 ANSI 解析导致乱码。

> 这三点对 C# 实现无影响（C# 无此类解析歧义），但说明"脚本能跑"不等于"逻辑正确"，
> 正式实现仍需单元测试兜底。

### 3.4 环境缺口

- `dotnet` 命令存在但 **SDK 未安装**（只有 8.0.8 运行时）。M1 前必须 `dotnet --list-sdks` 能看到 8.0.x。
- 无 `rustc` / `cargo` / MSVC Build Tools，进一步确认放弃 Tauri 的决定是合理的（ADR-002）。
- WebView2 运行时 156.0.4314.58 已存在，若 M2 需要切换到 WebView2 + React 备选方案，无需额外安装。

## 4. 对实现的影响

1. **采集层没有技术风险**：三个核心信号（窗口、空闲、画面）在本机全部可用，无权限阻挡，
   没有杀软拦截，开销可忽略。
2. **判定模型的阈值需要用真实数据标定**，不能靠拍脑袋。M1 增加一项交付：
   `focusledger calibrate --days 7`，输出各特征的分位数与建议阈值。
3. **媒体与锁屏信号是剩余风险点**，必须在 M1 的 C# 采集器里第一时间验证，
   因为它们直接决定 S2（看网课）和 S7（锁屏过夜）两个场景能否通过。
